2. Literature review (Robert) — max 1 page, min 2 paragraphs

Build the source table before you write a single sentence:

# Citation (IEEE) The one statistic you'll use Page / quote URL Date accessed

Then write three movements, in paragraphs:

  1. Problem context — the broader issue. Healthcare access for migrants and newly arrived people; unfamiliar insurance; emergency situations.
  2. Evidence — the numbers, each with a [n]. Look for: RSSB, Rwanda FDA, NISR, Ministry of Health / RBC, WHO, World Bank, and published studies on health access for mobile/migrant populations.
  3. Gap identification — what existing tools miss and why a mobile app fixes it. This is where your pharmacy-door insight goes — that acceptance information is public but only physically readable.

Rules: 5–7 sources. Numbered [1]…[n] in order of first appearance. Vary your language — do not start three consecutive sentences with "According to". Only cite what you have actually read. Prefer sources that name Rwanda; "pilot data from similar interventions in Kenya" is acceptable, "no country at all" is not.

3. Interviews (everyone) — the highest-value 3 days

The script — one script for everybody

The brief is explicit: the questions are the same, the answers differ. So build 5 warm-up + 8–10 core questions once, and reuse it 12 times.

Cover these six areas:
1. How they handle it today — "Walk me through the last time you needed medicine here."
2. The insurance moment — "How did you find out which pharmacy takes your insurance?"
3. The workaround — "What do you do when you're not sure?"
4. The cost of the problem — time, money, trips, stress. Ask for a real example, not an opinion.
5. The emergency case — "What would you do at 11pm with a sick child?"
6. What would change it — "What would have made that easier?"

Rules that decide whether you get good data

  • No yes/no questions. "Do you use X?" ✗ → "How do you handle X today?" ✓
  • Never describe our app before asking about the problem. The moment you do, every answer after it is contaminated.
  • Same questions for everyone. If you improvise new ones, you can't compare.
  • Ask "why" and "what" and then stay quiet. Silence gets you the real answer; the second sentence a person says is usually the honest one.
  • Write quotes verbatim, in their words — 2–3 per person. You will need them for the empathy maps, the personas and the insights summary.
  • Record the observation too: mood, hesitation, when they laughed, what they reached for. The rubric grades "rich evidence".

Consent — read it, then record the answer

"Before we start — this is for a university project. I'd like to record so I can write accurate notes. Nothing is shared publicly, your name isn't used, and you can stop or skip any question. Do you consent to being recorded?" (wait for a spoken yes — on the recording)

Keep the signed/scanned consent form. Five points live in this row.

Bias — the brief names five, so show you handled them

Same questions for everyone (not just the answers you hoped for) · a diverse set of participants, not 12 clones of yourselves · never lead · record everything so you don't remember only the first and last thing said · do not pivot the problem statement because you already spent time on it (sunk cost).

4. Synthesis (Saturday afternoon)

Empathy maps. Brief says one per user; rubric only requires 3–4 key ones. Do 4 rich maps and put direct quotes + sensory notes in them.
- Quadrants: SAYS · THINKS · DOES · FEELS
- Plus Sights · Sounds · Feels · Smells — non-negotiable, it's in the rubric
- Build one FigJam template, duplicate it four times. ~10 minutes each.

Aggregated maps. Merge the 4 into 1–2 segments. Name the segments by behaviour, not by person: e.g. "the caller" (phones the insurer), "the walker" (physically checks doors), "the asker" (asks friends/pharmacy staff).

Personas — 2. Rubric wants name, photo, demographics, goals, frustrations, behaviours, environment, and a quote. The photo and environment are the two people forget. The quote must be something a real person actually said.

Insight summary. Number conducted + the 5 strongest insights, each with a supporting quote and which participants said it.

Then fill the Claims → Evidence table in Team-Tasks-Round1.md. One table defends six rubric rows.

5. Competitors & journey map (Elie, Sunday)

Four competitors: 2 direct, 2 indirect.
- Direct = same offering, same audience (a provider/medicine finder for newcomers)
- Indirect = similar offering, different audience, or different offering, same audience (maps, insurer apps, WhatsApp word-of-mouth, government service portals)

Look internationally — the strongest comparables are the "find a provider that takes my insurance" products from other markets. Using them is fully legitimate and is exactly what the brief's direct/indirect split is for. Whatever you pick, verify each one is real and currently available before you put it in the document.

Screenshot every key screen. Note pricing, app-store rating, and — most valuable — read the 1- and 3-star reviews and write down the complaints. Free differentiation evidence.

Journey map: one DIRECT competitor. Stages → actions → thoughts → feelings/emotional curve → pain points → Opportunities.

Rubric, verbatim: "the 'Opportunities' column explicitly lists concrete, actionable improvements that map to your later Figma features."
So every opportunity must name a screen Deborah will build. "Better UX" is not an opportunity. "Show accepted insurers on the search results card so the user doesn't open each pharmacy" is.

6. UVP & reframed problem (Robert, Sunday)

UVP — one statement. Benefit + how it solves the need + what makes it different. The one you already have is strong because the gap is concrete:

The existing thing is a board on a door. Nobody has put it online.

Reframed problem — separate requirement, don't just repeat the original. Write it from the user's perspective, first person, supported by what they actually told you. E.g. "I have insurance I can't use, because I can't find out who takes it without walking there." Pull the wording from a real interview quote.

7. IA, flows, storyboard (Elie, Sunday)

IA — 8 screens minimum. A sitemap showing hierarchy and how screens connect. Apply the two principles the brief names: Choice Principle (few, well-organised options) and Focused Navigation (logical menu design).

User flows — one per core task. At minimum: onboarding → first successful search, and one supporting task. Must show actions, decision points, happy path AND failure states (wrong input, no network, no results found, pharmacy closed).

Storyboard — 6 panels. Characters, setting, emotions. One person's story: has the problem → finds the app → resolves it. Cheapest 5 points in the assignment; do not skip it.

8. Figma (Deborah + Igihozo, Sunday–Monday)

Order of work matters — build it this way and you save hours:

  1. Tokens + components first. Type scale, colour palette, buttons, cards, list rows, icons. Everything after this is assembly, not design.
  2. 60-30-10 colour rule — named in the brief, so it's marked. Mostly light neutrals, one brand colour, one accent for the primary action.
  3. 10 screens, covering the full journey: open → pick insurance → locate → see accepting pharmacies → choose → get there. Plus Home, Profile, Settings, Emergency.
  4. States: empty (no results found), loading, tap/hover, error (no network). Rubric names these explicitly.
  5. Real interactions: clickable links, transitions, at least one simulated state change. A flat picture of screens is not an interactive prototype.
  6. Share → anyone with the link → test in incognito. Do this Monday, not Wednesday.

Make the research visible. Under each key screenshot, one short caption naming the insight or journey pain point it answers. The rubric asks for screens that "map explicitly to the empathy map, journey map and UVP". Twenty minutes of captions defends several rubric rows at once.

10. Originality — the gate that can zero us

We write the proposal ourselves, in our own words, from our own interview notes.

AI is permitted only to fix grammar on text already written — the rubric phrases it as ">50% AI-generated content (limited to brainstorming/editing assistance)". Brainstorming and editing are the allowed lanes. Generating the narrative is not.

Our defence is structural: every claim traces to a quote or a named source. An AI could not have produced your interview transcripts, your sensory notes, or your verbatim participant quotes.

Keep evidence: the Google Doc version history, your handwritten notes, the raw audio. If we're ever asked, that is the proof.
